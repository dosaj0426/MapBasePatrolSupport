# 스마트 순찰 개발 환경

React + TypeScript + CSS, Python + FastAPI + Uvicorn 구성입니다.

## 실행

프로젝트 루트의 **서버 구동기.bat**을 더블클릭하면 콘솔창 하나에서 백엔드와 프론트엔드를 함께 실행합니다. 데모 음성은 브라우저 기본 한국어 TTS를 사용하며 별도 음성 작업자를 실행하지 않습니다. 로그는 `[백엔드]`, `[프론트]`, `[음성]`으로 구분합니다. `Ctrl+C`로 두 서버를 함께 종료하며, 콘솔창을 닫아도 구동기가 실행한 하위 프로세스를 함께 정리합니다. 이미 8000 또는 5173 포트가 사용 중이면 기존 서버를 유지하고 안내 후 실행을 중단합니다. 기존 방식으로 실행 중인 서버는 한 번 종료한 뒤 새 구동기를 사용하세요.

아래는 서버를 개별 실행할 때의 명령입니다.

백엔드 폴더에서 다음을 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

프론트엔드 폴더에서는 `npm install` 후 `npm run dev`를 실행합니다. 설치된 환경에서는 설치 단계를 생략합니다. pnpm 재현 설치는 `pnpm install --frozen-lockfile`, 백엔드 전체 검증 버전은 `requirements.lock.txt`입니다.

- 관리자: http://127.0.0.1:5173/admin
- 순찰자 선택: http://127.0.0.1:5173/user
- 개별 순찰자: `/user/1`, `/user/2`처럼 생성된 번호로 접속
- API 문서: http://127.0.0.1:8000/docs

## 지도와 주소 검색 설정

`frontend/.env`의 `VITE_NAVER_MAP_KEY_ID`에는 브라우저용 Maps 키 ID만 입력합니다. 콘솔에 개발 Web 서비스 URL을 등록하고 프론트엔드를 재시작합니다.

`backend/.env.example`을 `.env`로 복사하고 `NAVER_MAP_KEY_ID`, `NAVER_MAP_KEY_SECRET`을 입력합니다. 해당 Application의 **Geocoding 활성화**가 필요합니다. 비밀키는 프론트엔드에 넣지 않습니다. 백엔드를 재시작한 뒤 관리자에서 도로명 주소를 검색합니다. 우편번호 찾기는 페이지 내부에 Kakao 주소 검색창을 열며, 선택한 도로명 주소를 네이버 Geocoding으로 좌표 변환합니다. 검색 결과를 선택해야 지점을 저장할 수 있습니다.

로컬 HTTP에서 네이버 SDK의 일부 HTTP 요청이 실패하는 환경을 위해 개발용 `map-transport.js`가 지정된 지도 GET 요청만 공식 HTTPS 서버로 전달합니다. 별도 타일 캐시는 없습니다. 운영은 HTTPS로 제공합니다.

## 관리자 기능

- 도로명 주소 검색 결과를 지도에서 확인하고 지점 등록·수정·삭제
- 여성 1인 사업장 등 분류 선택, 상세 주소 입력, 분류별 아이콘 자동 지정
- 이름으로 아이콘 검색, PNG/JPEG/WebP 업로드(최대 2MB), 서버에서 PNG로 정규화
- 순찰자 생성·이름 변경, 개별 접속 주소 제공
- 5초마다 순찰자 위치 갱신, 마지막 수신 시각과 GPS/데모 구분 표시
- 순찰 기록 선택 시 저장된 경로를 지도에 표시
- 범죄예방 강화구역의 반지름, 알림 타입, 음성 문구 설정 및 저장 전 범위 미리보기

강화구역은 중심에서 반지름 이내로 들어오면 한 번 알립니다. 반지름에 고정 완충 거리 10m를 더한 경계를 벗어나야 다음 진입 알림이 활성화됩니다. 예를 들어 반지름 50m이면 60m 밖으로 나간 후 재진입해야 다시 알립니다. 완충 경계는 지도에 표시하지 않습니다. GPS 정확도 100m 초과 및 짧은 시간의 비정상적인 GPS 점프는 서버 판정에서 제외합니다. 구역 설정 수정 시 진입 판정 상태를 초기화합니다.

## 순찰자 기능과 저장

처음 접속하면 GPS 권한을 요청하고 현재 위치를 표시합니다. GPS 사용이 불가능하면 부산진경찰서 기준 데모를 제공합니다. 방향키 한 번으로 10m 이동하며 Shift + 지도 좌클릭으로 해당 위치로 이동합니다. 데모 이동은 GPS 추적과 위치 고정을 해제합니다. 위치 고정 버튼으로 다시 중앙 추적할 수 있습니다.

순찰 시작·종료는 서버에 저장합니다. GPS·방향키·Shift 클릭 경로를 파란 선으로 연결하며, 서버 전송은 5초 간격으로 처리합니다. 종료 시 남은 좌표 전송이 완료되어야 종료 처리합니다. 좌표 순번으로 중복 저장을 방지하며 전송 실패 시 화면에 오류를 표시하고 재시도합니다. 새로고침하면 서버에 저장된 진행 중 순찰을 복구합니다. 아직 전송하지 못한 좌표는 메모리에 있으므로 탭을 닫거나 새로고침하면 잃을 수 있습니다.

GPS 경로에는 3m 최소 이동, 정확도 100m, 추정 속도 70m/s 필터를 적용합니다. 데모 이동에는 이동 거리·속도 필터를 적용하지 않으며 기록과 알림에 데모임을 표시합니다. 경로는 수집 좌표를 직선으로 연결합니다.

강화구역 알림과 확인 상태는 서버에 저장됩니다. 새 알림은 오른쪽 위에 펼쳐지고 클릭하면 회색으로 바뀝니다. 모두 확인하면 벨 버튼으로 접힙니다. 창 높이는 하단을 드래그하여 조절하고 내용은 내부에서 스크롤합니다. 색상은 `frontend/src/notificationTypes.ts`에서 변경합니다. 음성 안내는 기본 ON이며 브라우저·운영체제의 기본 한국어 TTS를 사용합니다. 기기에 따라 목소리가 다르며 한국어 음성이 설치되어 있어야 합니다. 브라우저의 자동 재생 제한이 있으면 첫 화면 터치 또는 키 입력 후 활성화되고, 대기 중 수신한 미확인 알림을 재생합니다. 관리자 미리듣기도 같은 기기 기본 TTS를 사용합니다.

## 데이터베이스와 개발 범위

기본 개발 DB는 SQLite `backend/data/patrol.db`입니다. 아이콘 파일은 `backend/data/icons`에 저장됩니다. 서버를 재시작해도 데이터가 유지됩니다. MySQL 사용 시 미리 데이터베이스를 생성하고 `backend/.env`에 다음 형식으로 설정합니다.

```dotenv
DATABASE_URL=mysql+pymysql://USER:PASSWORD@127.0.0.1:3306/patrol?charset=utf8mb4
```

현재 검증은 SQLite로 진행했습니다. 기존 데이터의 MySQL 자동 이전은 제공하지 않습니다. DB와 아이콘 폴더를 함께 백업해야 합니다.

현재 `/admin`, `/user/번호`는 Capability 링크로 인증된 세션이 있어야 접근할 수 있습니다. 관리자·순찰자 API 권한을 서버에서 검사합니다. 실제 경찰 데이터는 포함하지 않았습니다. 위치 전송은 브라우저가 실행 중일 때 동작하며 모바일 화면 꺼짐 상태의 백그라운드 추적은 보장하지 않습니다.

## 로컬 AI 음성

현재 데모에서는 브라우저 Web Speech API로 기본 한국어 음성을 재생합니다. 아래 Qwen3-TTS 안내는 선택적으로 보존한 이전 방식이며 기본 실행에서는 사용하지 않습니다. 관리자 미리듣기도 기기 기본 TTS를 사용합니다.

통합 구동기의 백엔드는 자동 reload를 끈 상태로 실행합니다. Python 코드 또는 .env 변경 후에는 구동기를 재실행하세요. 모델 캐시 생성에 따른 불필요한 서버 재시작을 방지하기 위한 설정입니다.

## 순찰자 방향 화살표

순찰자 화면과 관리자 지도에 회전하는 내비게이션 화살표를 표시한다. 북쪽 0°, 동쪽 90°, 남쪽 180°, 서쪽 270°를 사용하며 지도는 북쪽 고정을 유지한다.

- 휴대폰의 절대 방향 센서(지원 시 webkitCompassHeading 우선)를 사용한다. 상대 자이로 회전만 제공하면 나침반으로 사용하지 않는다.
- 방향 센서는 기본으로 자동 사용하며 별도의 켜기 버튼은 없다. iPhone 등 권한이 필요한 브라우저는 첫 화면 터치 또는 키 입력 시 권한을 요청한다. HTTPS 또는 localhost가 필요하다. 센서 미지원·권한 거부 시 기존 GPS·이동 방향을 사용한다.
- 최근 유효한 센서 값이 없으면 GPS 이동 방향, 또는 충분히 이동한 좌표 사이의 방위각을 사용한다. GPS 정확도가 나쁜 경우와 작은 위치 흔들림은 방향 계산에서 제외한다.
- 방향키·Shift 클릭 데모에서는 이동한 방향으로 회전하고 센서 방향이 데모를 덮어쓰지 않는다.
- 방향 정보가 아직 없으면 회색 화살표로 표시하며, 정지 시 마지막 유효 방향을 유지한다.
- 북쪽 경계(359°→1°)는 짧은 방향으로 회전한다. 센서 값은 완만하게 반영한다.
- 실제 휴대폰 센서 정확도·자기장 영향·세로/가로 화면 전환은 기기별 현장 검증이 필요하다. 이 기능은 기기 방향이며 사람의 시선이나 몸 방향을 직접 측정하지 않는다.
- 방향은 위치와 별도로 최대 초당 4회 서버에 전송하고, 관리자는 SSE로 약 1초 간격으로 변경을 받는다. 정지한 상태의 회전도 반영하며 방향만 변경되어도 순찰 경로나 위치 수신 시각을 변경하지 않는다. SQLite에 마지막 방향·출처·측정 시각을 저장한다. 기존에 열린 순찰자 화면은 새로고침해야 방향 전송이 시작된다.

검증: frontend에서 `pnpm test`와 `pnpm run typecheck`.
참고: https://developer.mozilla.org/en-US/docs/Web/API/DeviceOrientationEvent


## 관리자 순찰 상세 결과

순찰 기록을 선택하면 왼쪽 바가 세부정보로 전환되고 지도에 경로와 시작·종료 위치를 표시합니다. 뒤로가기 버튼으로 필터를 유지한 목록으로 돌아갑니다. 진행 중 기록은 5초마다 갱신하며 종료 시 최종 결과를 저장합니다.

새 순찰은 시작 시 강화구역의 이름·위치·반지름·고정 완충 거리 10m를 보관합니다. 기존 순찰 스냅샷의 과거 배수 설정은 유지합니다. 구역 안 위치 표본으로 첫 진입을 집계하며 외곽 완충 범위를 벗어난 후 재진입해야 횟수가 증가합니다. 체류 시간은 직전 표본이 원 안에 있었던 구간의 추정치이고 30초 초과 공백은 제외합니다. 데모 순간이동도 도착 표본으로 판정하며 중간 통과는 추정하지 않습니다. 겹치는 구역은 각각 집계합니다. 이동 거리는 저장된 좌표 간 직선 거리입니다.

종료 결과는 DB에 저장하여 이후 구역 수정·삭제에 영향받지 않습니다. 기존 기록은 당시 구역 정보가 없어 현재 설정으로 재계산하고 참고 결과로 표시합니다. 실제 연속 체류 시간과 GPS 표본 기반 추정은 다를 수 있습니다.


## TypeScript 개발

2026-10-21 프론트엔드를 TypeScript로 전환했습니다. 화면은 `.tsx`, 로직과 테스트는 `.ts`를 사용합니다. Python 백엔드와 CSS, 브라우저가 직접 실행하는 `public/` 스크립트는 유지합니다.

- `frontend/src/types.ts`: 서버 데이터·좌표·알림·순찰 결과 타입
- `frontend/src/naverTypes.ts`: 앱에서 사용하는 네이버 SDK 범위의 타입
- `frontend/tsconfig.json`: strict 타입 검사, 출력 파일 생성 없이 검사
- `pnpm install --store-dir .pnpm-store`: 의존성 설치
- `pnpm run typecheck`: 화면·로직·테스트 타입 검사
- `pnpm test`: 방향·위치·경로 테스트
- `pnpm run build`: 타입 검사 통과 후 Vite 빌드

TypeScript 타입은 실행 시 제거되므로 외부 데이터의 실제 값 검증과 백엔드 Pydantic 검증은 계속 필요합니다.


## 지점 관리 목록과 상세정보

지점 관리의 기본 화면은 지도 중심에서 가까운 순의 목록입니다. 지도 이동 완료 시 거리를 다시 계산하며 거리는 직선 거리입니다. `새 지점 등록` 버튼으로 등록 화면에 들어가고 지점 카드·지도 마커를 클릭하면 상세정보로 이동합니다. 상세정보에서 수정·삭제·목록 복귀를 제공합니다.

과거 점검 기록은 최근 종료 순찰 200건 중 해당 강화구역 진입 실적이 있는 순찰을 조회합니다. 순찰자, 진입 횟수, 추정 체류 시간, 최근 진입 시각을 표시하고 기록 선택 시 해당 순찰의 경로·결과를 엽니다. 이 기록은 자동 순찰 방문 이력이며 수동 현장 점검표나 점검 완료 판정은 아닙니다. 기존 기록의 재계산 값은 참고 기록으로 구분합니다.


## 지도 클릭으로 지점 등록

새 지점 등록·수정 화면에서 지도를 클릭하면 SDK가 계산한 클릭 좌표를 지정하고 서버의 `/api/reverse-geocode`로 주소를 조회합니다. 도로명 주소 우선, 지번 주소·지역명 순으로 사용하고 제공된 우편번호를 입력합니다. 지점 이름·아이콘 등은 관리자가 지정한 뒤 저장합니다. 자동 조회로 저장까지 진행하지 않습니다.

네이버 Maps Application에서 Reverse Geocoding을 활성화해야 하며 서버 키 권한이 필요합니다. 조회 실패·주소 미제공 시 선택 위치를 유지하고 등록 주소를 직접 입력할 수 있습니다. 주소 직접 수정은 지도 좌표를 바꾸지 않습니다. 연속 클릭 시 이전 조회 응답이 새 위치를 덮어쓰지 않도록 처리합니다.


## 순찰자 추가·제거

관리자 → 순찰자에서 이름을 입력해 생성하고 개별 접속 주소를 발급합니다. 카드의 순찰자 제거 버튼은 확인 후 목록·지도에서 해당 순찰자를 제외하며 서버에서도 조회·위치·방향 전송·새 순찰 시작을 차단합니다. 진행 중인 순찰이 있으면 먼저 종료해야 제거할 수 있습니다. 데이터는 비활성 상태로 보존하므로 과거 순찰 경로·결과·순찰자 이름은 계속 조회할 수 있으며 번호는 재사용하지 않습니다.


## Capability URL

관리자 최초 접속 링크는 `.tools/admin-access-link.txt`에 저장합니다. 관리자 → 순찰자 카드에서 전용 링크를 발급·복사·폐기할 수 있습니다. 링크 없는 접속과 다른 순찰자 데이터 접근은 서버에서 차단합니다.


## CSV 위치 일괄 등록

관리자 지점 관리의 `위치 파일 추가` 버튼에서 CSV를 검사하고 미리보기 후 전체 등록합니다. 필수 열은 지점명·분류·도로명주소이며, 최대 50행·1MB를 지원합니다. 오류·중복은 행별로 표시하고 오류가 있으면 전체 등록을 막습니다. 예제·빈 양식은 `examples/`와 화면의 다운로드 버튼에서 제공합니다.


## 순찰자 화면 설정

알림 왼쪽 설정 아이콘에서 음성 안내와 범죄예방구역 원형 범위를 켜고 끕니다. 구역 표시 토글은 실제 진입 범위 원에만 적용하며 지점 아이콘과 진입 알림은 유지합니다. 선택한 설정은 같은 브라우저에 저장합니다. 햄버거 메뉴에서는 음성 안내·순찰자 선택·화면 선택·관리자 화면 이동 항목을 제거했습니다.


## 사용자 기준 방향 음성 안내

강화구역 진입 시 순찰자 위치에서 구역 중심까지의 방위각과 기기 방향(미지원 시 GPS·데모 이동 방향)을 비교합니다. 안내는 `좌측에 정보공학관이 있습니다.`, `우측에 부산진경찰서가 있습니다.`, `전방에 CCTV가 있습니다.` 형식이며 한글 이름의 받침에 따라 이·가를 선택합니다. 별도 안내 문구가 있으면 방향 문장 뒤에 이어서 읽습니다.

정면 ±20°는 전방, 뒤쪽 ±20°는 후방, 나머지는 좌측·우측입니다. 방향이 없거나 위치 측정 시각보다 10초 넘게 오래되면 방향을 생략합니다. 중심까지 거리가 3m보다 가깝거나 GPS 정확도 범위 안에 있으면 좌우를 단정하지 않습니다. GPS 위치와 방향의 출처가 다를 때도 생략합니다.

이동 좌표에는 당시 방향과 측정 시각을 함께 담아 지연 전송 시 최신 방향과 과거 위치가 섞이지 않도록 했습니다. 전송 재시도만으로 방향 측정 시각을 새로 만들지 않습니다. 방향 문구는 진입 순간 기준으로 저장되어 이후 알림 확인 시 재계산하지 않습니다. 구역 중심 기준이며 실제 건물 출입구 위치와 다를 수 있습니다.

새로운 방향별 문장은 기기 기본 한국어 TTS로 재생하며 서버 음성 생성 요청을 보내지 않습니다. 이전에 저장된 알림 내용은 유지되며 새 진입 알림부터 적용됩니다.


관리자 첫 진입 시 지도 중심은 동의대학교 가야캠퍼스(엄광로 176)입니다. 가까운 지점 목록도 이 중심에서 시작하며 지도 이동 시 다시 정렬합니다. 순찰자 화면의 GPS 중심 설정은 그대로 유지합니다.


## 모바일 길게 눌러 데모 이동

순찰자 설정의 `꾹 눌러 위치 이동`을 켜면 브라우저의 기본 터치 이벤트를 직접 감지하여 한 손가락으로 1초간 누르면 즉시 데모 위치를 변경합니다. 12px 이내 손떨림은 허용하고, 드래그·다중 터치·터치 취소 시 이동을 취소합니다. 화면 픽셀을 직접 환산하지 않고 지도 SDK touchstart 이벤트의 coord/latlng를 이동 목표로 사용합니다. 누르는 도중 확대·축소·화면 크기 변경 시 해당 이동을 취소합니다. 기본 OFF이며 같은 브라우저에 선택을 저장합니다. GPS 추적과 위치 고정을 해제하고 순찰 중이면 기존 Shift 클릭과 동일하게 경로에 추가합니다. 실제 기기의 GPS 값을 바꾸지는 않습니다.

지도 드래그·핀치·줌 동작에서는 해당 길게 누르기 동작을 취소합니다. 좌표는 SDK 이벤트에서 받아 확대 비율에 따라 직접 계산하지 않습니다. 토글을 끄면 이벤트를 해제합니다. 실제 모바일 터치 동작은 기기별 확인이 필요합니다.


관리자 지도에서 순찰자 화살표를 클릭하거나 순찰자 관리 카드의 `순찰 경로 보기`를 누르면 현재 진행 중인 순찰의 경로와 세부정보를 표시합니다. 경로는 서버에 저장된 좌표를 5초마다 갱신하며 순찰 종료 결과도 반영합니다. 같은 기록을 갱신할 때 지도 시점을 반복 초기화하지 않습니다. 대기 중인 순찰자는 현재 위치만 표시합니다.

꾹 눌러 위치 이동을 켜면 GPS watch를 중단하고 늦게 도착한 GPS 콜백도 무시합니다. 기기 방향 센서는 데모 좌표에서도 계속 사용하며, 센서 미지원 시 데모 이동 방향으로 대체합니다. 설정을 끄거나 메뉴에서 실제 GPS 위치 사용을 선택하면 GPS 추적과 내 위치 고정을 다시 시작합니다.

이전 선택형 로컬 TTS 방식(PATROL_LOCAL_TTS=1일 때만): 서버 시작 및 강화구역 저장 시 일반·전방·후방·좌측·우측의 실제 알림 문구를 WAV로 미리 생성합니다. 캐시가 있으면 다시 생성하지 않습니다. 기존 지점은 서버 시작 후 백그라운드에서 순차 준비하며, 준비 전 첫 알림이나 수정한 문구는 생성 시간이 걸릴 수 있습니다. 위치 전송 및 알림 조회 주기는 현재 5초입니다.

현재 데모 기본값: 브라우저 speechSynthesis(ko-KR), 음성 안내 ON/OFF 유지, 방향 문구 유지, 관리자 즉시 미리듣기. 서버 구동기는 8001 음성 모델을 실행하지 않으며 사전 생성도 하지 않습니다. 기존 로컬 TTS 자산은 삭제하지 않았습니다. 이전 엔진을 별도로 실행하려면 구동기 --local-tts 옵션이 필요하나 현재 화면은 기본 TTS를 사용합니다.

재접속 알림: 최초 알림 조회는 기존 미확인 알림을 목록에만 복원하고 음성은 재생하지 않습니다. 이 초기 조회를 위치 전송보다 먼저 수행하므로 이후 좌표 전송으로 생성되는 새 진입 알림은 정상 안내합니다. 이후 새로 수신한 미확인 알림만 한 번씩 안내하며 중복 ID는 무시합니다.

## 지점 분류와 강화구역 범위

- 지점 등록·수정에서 분류 드롭다운을 선택하면 해당 분류의 아이콘이 자동 지정됩니다. 기존 아이콘 메뉴는 지점 분류 메뉴로 바뀌었으며 분류 이름·이미지를 함께 등록·수정할 수 있습니다. 같은 분류를 사용하는 지점은 변경 사항을 함께 반영합니다.
- 지도에는 실제 진입 반지름의 원만 표시합니다. 중복 진입 방지용 외곽 원과 배수 입력란은 제거했습니다.
- 재진입 판정은 반지름 + 10m 고정 완충 거리입니다. 경계보다 멀리 이탈한 뒤 실제 진입 원 안으로 돌아오면 다시 알립니다. 서버에서 강제하며 기존 CSV의 완충배수는 무시합니다.
- 위치를 지정하고 강화구역을 켜면 저장 전에도 파란 원을 미리 표시합니다. 반지름·위치 변경을 즉시 반영하며 취소하거나 화면을 나가면 제거합니다.
- 기존 지점은 이름과 이미지를 보존하면서 분류에 연결합니다. 이미 종료된 순찰의 저장된 결과와 과거 설정 스냅샷은 다시 쓰지 않습니다. 새 순찰 스냅샷에는 고정 완충 거리를 명시합니다.
- CSV는 지점 분류 목록의 이름을 사용하며 아이콘을 별도로 선택하지 않습니다. 기존 아이콘이름 열은 비우거나 분류와 동일하게 지정해야 합니다.
